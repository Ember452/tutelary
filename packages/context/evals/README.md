# M1 评测集（docs/09 M1 可判定判据）

为什么必须真实日志：**对想象负载调参是本项目认定的最大学习陷阱**（docs/09 M1 关键纪律）。你需要提供 3–5 段真实对话日志（自己的工作流即可，无需公开）加每段的人工标注，此后"压缩质量"只认下面两条机器可判的硬指标。

## 放置位置与格式

`cases/` 目录下每案一个 JSON 文件：

```json
{
  "id": "case-001",
  "transcript": [
    {"role": "user", "text": "……真实对话原文……"},
    {"role": "assistant", "text": "……"}
  ],
  "budget": {"total": 8000},
  "must_survive": ["必须原样保留的关键事实或决定", "……"]
}
```

- `transcript`：真实对话原文（可脱敏，但**不要改写语言风格与长度分布**——那正是要测的东西）；
- `budget.total`：这案要压到的总预算；档位建议每案至少两档（宽松/紧张）；
- `must_survive`：压缩后必须原样保留的字符串，人工从原文里挑。

## 运行

```bash
uv run python packages/context/evals/run_evals.py
```

- 全过：逐案 ✓ 表，退出码 0；
- 任一失败：退出码 1，并打印未达标项；
- `cases/` 为空：打印"等待真实日志"并正常退出——这是**待验收**，不是失败。

## 两条硬指标

1. **预算达标**：压缩后 history 实测 tokens ≤ 预算 history 段；
2. **must-survive 全保留**：每条标注都出现在压缩输出中。

调参底稿（策略参数怎么改、为什么）记录在本目录 `NOTES.md`，作为 M5 deep-dive 的素材。
