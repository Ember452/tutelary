## 2. 结构决策与 why

- **记忆 Hub 延后**：08 的包职责提到"记忆 Hub"，但 Hub 的写路径广播需要"一个端口多个提供者"的组合语义——这是 M3 预期内的端口增补区（组合根怎么装多个 Policy/Memory）。M2 不为它新造机制，先交付 MarkdownProvider。
- **policy 是纯对象而非 Component**：Policy.check 无副作用（04 §2），组合子需要拿子策略**实例**；而装配器的端口是单提供者语义，装不下"多个 Policy 组合"——这同样是 M3 端口增补议题。M2 交付纯实现，M3 引擎落地时随 ADR 决定装配面。
- **seed 是契约套件的测试面**：Memory 端口无写方法（写路径走事件），但套件要播种——约定实现暴露 `seed(scope, text) -> str`（04 §4 同步）。
- **markdown 文件布局**：`root/<agent>/<session|_global>/<turn_id>.md`；TurnCommitted 不带 agent，事件落盘记 `_shared`（对任意 agent 可见）；幂等 = 同 turn_id 文件已存在即跳过。
- **文件 IO 全部经 `asyncio.to_thread`**：AGENTS §4.4 禁止在事件循环里做阻塞 IO；seed 是同步测试面（明确文档化）。
- **Subprocess 不做网络隔离**：诚实文档化——`network=False` 对子进程无强制力，真断网靠 DockerRuntime（`--network none`）。
- **docker SDK 惰性导入**：架构门禁 4 强制；未安装/守护进程不可用 → `SandboxUnavailableError`；真实容器测试进 docker-marked 车道，默认排除。
- **超时自守**：`ExecSpec.timeout_seconds` 为 None 时沙箱兜底 60s（04 §2"超时自守"）。

## 3. 契约套件检查（memory，按 04 §4）

1. 种子后同 scope recall 命中；2. load_context 含种子内容；3. 派发 TurnCommitted 落库、重复派发幂等；4. 无命中返回 `[]` 不抛错；5. shutdown 幂等不抛错。检查 6（错误路径抛类型化错误）对 memory 不适用——它的契约本身就是"无命中不抛错"，不为凑数发明错误场景。

## 5. 实现逼出的修订（同任务同步，工作草案规则）

- **`_shared` 段只解除 agent 隔离**：会话过滤对事件落盘的记忆照常生效（首版语义过宽，store 测试逼出修正）。
- **MarkdownMemoryConfig root 缺省化**：契约套件的"可无配置装配"规则倒逼——`model_validate({})` 落到 `./tutelary-memory` 默认值。
- **safe_stem 清理开头连点**：`../evil` 不能生成 `.._evil.md` 这类名字。
- **seed 是套件测试面**：Memory 端口无写方法，播种约定为 `seed(scope, text) -> str`（04 §4 已同步）。
- **隔离矩阵测试依赖**：沿 M1 的措辞，pytest + pytest-asyncio 为包内测试的最小测试依赖。
