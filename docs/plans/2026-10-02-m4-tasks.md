## 2. 结构决策与 why

- **基准放顶层 `benchmarks/`，不进任何组件包**：基准要同时测内置实现与第三方 adapter——放进 tutelary-memory 就迫使 adapter 反向依赖它，破坏中立。08 顶层树同步修订（工作草案规则）。
- **adapter 按第三方姿态发布**：发行名 `tutelary-mem0-adapter`、**顶层导入名 `tutelary_mem0_adapter`**（`langchain-openai` 之于 langchain 的形态，01 §5）——官方 adapter 的职责就是首次验证这条生态故事；它只依赖 core，mem0ai 是可选 extra、惰性导入（docker SDK 同款纪律）。
- **mem0 客户端可注入**：适配逻辑（映射、幂等、user_id 作用域）用注入的 fake client 离线测试；真实 mem0 需要 LLM API，跑分属用户环境——基线的 Mem0 行因此留待 API 环境（与 M1 评测集同款诚实处理）。
- **指标三条，全部机器可判**：recall_hit_rate（期望命中全部召回的查询占比）、mean_precision（召回结果中相关项占比，防"全召回刷分"）、scope_isolation_ok（agent 作用域互不串扰）；延迟取 repeats 的 p50/p95 作参考（不同实现存储介质不同，不进验收）。
- **workload 确定性**：固定种子集与查询集（含多命中、无命中两个边界），零随机——结果可复现由协议保证。

## 3. 对比报告的诚实边界

`REPORT.md` 内置行由本仓库跑出；**Mem0 行留待所有者在有 `mem0ai` + LLM API key 的环境执行**：
`uv run --extra mem0 python benchmarks/memory/run_benchmark.py --factory tutelary_mem0_adapter.testing:make_mem0_factory --output benchmarks/memory/results/mem0.json`
（mem0 的记忆抽取本身要调 LLM，Mock 它等于伪造基准。）09 §5 的 M4 因此不勾选完成，与 M1 同款留待。

## 5. 实现期修订（同任务同步，工作草案规则）

- **benchmarks 成正式包树**：加 `__init__.py`——CLI 直跑与 pytest 共用同一条绝对导入路径。
- **mem0 版本差异防御**：search 返回的 dict 包裹/裸列表两种形态都映射；precision 比较必须用记忆**文本**而非 key（自测逼出）。
- **事件写路径的 user_id**：TurnCommitted 不带 agent，mem0 侧取 session（缺省 "shared"）。
- **隔离矩阵 key 用目录名**（`mem0_adapter`），发行名映射进 DIST_NAMES。
- **pyright 书面豁免**：mem0 惰性导入的 unresolved-import——未安装本身就是被测路径。
