## 2. 结构决策与 why

- **根项目 `package = false`（virtual workspace root）**：08 规定根 `pyproject.toml` 只是"workspace 声明 + 工具配置"，且 M3 的伞包发行名就叫 `tutelary`——根项目若占这个名字，M3 加 `packages/runtime` 时会撞名。virtual root 让根不参与发行。
- **`.python-version` 钉 3.13**：uv 以它选解释器，保证所有人（和 CI）拿到同一主版本，避免 `requires-python = ">=3.13"` 漂移到 3.14。
- **环境命令 `uv sync --all-packages`**：根是 virtual workspace root，uv 默认只装根依赖；`--all-packages` 才把成员包可编辑安装进 venv（spike 附带发现，AGENTS §1 同步）。
- **`errors.py` 在 03 §1 五文件之外**：错误类型被 events/lifecycle/assembler 共同引用，独立成文件避免互相 import 打环。按工作草案规则，03 §1 在同一任务里更新。
- **fakes 放 `tutelary/core/fakes/`**：红线二（组件只准 import core）要求假实现在 core 命名空间内，组件与 only-* 示例才引用得到。
- **`examples/only-core.py` 作内核自己的 only-\***：内核没有组件可 only，09 验收第 4 条的"hello 装配"落进 08 §5 的 `examples/only-*.py` 约定。
- **pyright 用 basic 档**：AGENTS §4.3 只要求 pyright-clean；是否升 strict 留到 M3 整船时评估，避免 M0 就被类型细节拖住。
- **不做**：pre-commit 钩子、publish.yml、README/CHANGELOG（社区门面 M5 前齐备）。
- **ruff 关闭 RUF001/002/003、排除 `docs/`**：中文注释是项目规范，全角标点是纯噪声；ruff 0.16 会重排 markdown 里的 python 代码块，设计基线文档不许被工具重排。
- **契约插件的 pytest 例外**：`contract.py` 是随包发布的 pytest 插件，pytest 属 `[contract]` extra，不算运行时依赖——05 §4 已同步例外条款。

## 3. 第 0 天 spike 留痕

发布形态验证（09 M0 第 0 天）——PEP 420 命名空间的两个已知风险点：

- 验证①（workspace 可编辑安装）：**通过**——`uv sync --all-packages` 后 `import tutelary.core` 解析到源码树，editable 与 PEP 420 无冲突。
- 验证②（全新 venv 单装 wheel）：**通过**——`uv build` 产物在全新 venv 单装后 `import tutelary.core` 正常；wheel 内唯一 `__init__.py` 位于 `tutelary/core/`，无 `tutelary/__init__.py`。不触发降级预案。

附带发现：virtual root（`package = false`）下 `uv sync` 默认只装根 dev 依赖、不装 workspace 成员——环境命令定为 `uv sync --all-packages`（AGENTS §1 已同步）。

失败预案：降级 `tutelary_core` 式独立顶层包名（只动 08 命名规则，不动组件划分），动手前向所有者汇报。
