# ADR-0002 · 单仓多包（uv workspace），而不是每组件一个仓库

状态：已接受（2026-10-01）

## 背景

"每个组件独立发布"有两种实现：N 个独立仓库，或一个 monorepo 内 N 个包。cordis 本身就是 yarn workspaces monorepo——"独立发布"不等于"独立仓库"。

## 决定

单仓多包：uv workspace，`packages/*` 每目录一个发行包，PEP 420 原生命名空间 `tutelary.*`，tag 驱动 lockstep 全量发布。

## 理由

1. 拆包的正确性来自**边界**（架构测试 + 契约套件），不来自仓库物理距离；仓库距离反而制造版本同步与跨仓 CI 的额外税；
2. lockstep 版本 + 单 changelog 在 Python（无 peerDependencies 强制力）下维护成本最低；
3. 早期接口不稳定（端口会被第二实现逼着改版），单仓重构的原子性是保命符；
4. "可拆性"用隔离安装测试证明——边界对了，随时可以真拆，拆包是机械工作；边界不对，拆了也白拆。

## 后果

仓库体积随组件增长；需要 matrix CI 防止"顺手 import 兄弟包"（架构测试 + 隔离安装 job 双保险）。

## 重评触发

出现活跃的第三方贡献者生态、且单仓权限/发布流程成为真实瓶颈时再评估。
