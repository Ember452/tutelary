# ADR-0003 · 版本 lockstep 起步

状态：已接受（2026-10-01）

## 背景

cordis 生态每包独立版本（core 4.0.0-rc.10、timer 1.1.3……），靠 npm peerDependencies + 单版本去重维持兼容约束。Python（pip/uv）没有等价的生态强制力：同一环境难以让两个核心版本并存，兼容矩阵要靠人工与 CI 维护。

## 决定

全部发行包共享同一版本号；tag `vX.Y.Z` 一次发布全部 wheel。版本语义：端口签名变更 = major；事件/端口新增 = minor；实现内部变更 = patch。

## 理由

1. 兼容性表达从"版本数字游戏"收敛为契约测试套件——套件绿 = 兼容，比 version range 推断可靠；
2. 包多、消费者少的早期，N 套独立版本是纯税：发版脚本、兼容矩阵、文档同步全部翻倍；
3. lockstep 下"我该装哪个版本"永远只有一个答案，降低采用摩擦。

## 后果

单个组件的 hotfix 也要全量发版（可接受：wheel 构建是机械工作）；组件成熟度无法从版本号读出（用 CHANGELOG 分节补偿）。

## 重评触发

第三方实现 ≥3 个、且独立发布节奏成为真实需求时，立 ADR 评估把 core（慢速稳定）与组件包（快速迭代）拆成两条版本流。
